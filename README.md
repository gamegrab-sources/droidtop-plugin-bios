# droidtop-plugin-bios

An **unofficial** droidtop plugin from the [gamegrab-sources](https://github.com/gamegrab-sources) organisation. It is not
part of droidtop. It finds the BIOS, firmware and key files an emulator asks for and hands each one to droidtop to
download (Droidtop/tracker#392).

BIOS and firmware files are copyrighted works. Take only those of consoles you own; this plugin only knows where they
are, it hosts nothing.

## What it does

- **Knows the files.** Per system, the files and the MD5 of every dump droidtop accepts, from droidtop-platforms'
  `bios-database.json` (generated there from Batocera's registry). Plus the 3DS and Switch keys and firmware their
  emulators need, which that database has no rows for (`tools/extras.json`).
- **Knows where they are.** Single files with a SHA-256 and a size on
  [Abdess/retrobios](https://github.com/Abdess/retrobios) (GitHub), and the loose files of the LibRetro BIOS collection on
  the Internet Archive (`retroarch_bios`). 305 of 386 files have a source that holds exactly the dump droidtop lists.
- **Verifies.** A retrobios download carries its SHA-256 and size in the acquire reply, so droidtop checks the bytes.
  An Internet Archive file is chosen by its listed MD5 and size (droidtop's descriptor checks SHA-256 only, see
  Droidtop/tracker issues filed from this work). The plugin asks the source once (a HEAD request) that the file is
  there and its size is right before it starts the job.
- **Is configurable.** Settings: retrobios on or off, more Internet Archive items (it lists the item's files and picks
  the ones whose MD5 is on droidtop's list), and your own https address templates (`{file}`, `{system}`, `{md5}`).

## How it plugs in today

droidtop has no BIOS hook yet, so the plugin offers its files through `library.sources` (Get games, search, detail and
an acquire job): search lists a system's files (from the system you are in) or matches words across all systems. See the
issues filed on Droidtop/tracker for the hook the Emulator setup helper needs ("Get the BIOS for this system"), several
files in one acquire, and a place other than the games folder.

## Layout

- `src/plugin.py`: the whole plugin; standard library only; contained (no sockets: `net.http`, `data` through droidtop).
- `data/index.json`: generated by `tools/gen_index.py` from the three inputs it names. Re-run it to refresh the hashes
  and sources; nothing in it is typed by hand.
- `build.sh` embeds the index into `build/plugin.py` and writes `build/manifest.json`; `sign.sh` signs and packs
  `gamegrab.bios.droidplugin.tar.xz` (CI does both with the repository's key from the gamegrab-sources master).
- `test_plugin.py`: `python3 test_plugin.py` (CI runs it on the source and on the built file).
